# ZeroOmega WG для Windows

Личный форк ZeroOmega с профилями WireGuard и AmneziaWG. Обычные HTTP-, HTTPS-,
SOCKS4- и SOCKS5-прокси и правила auto switch остаются в привычном интерфейсе.
Дополнение управляет небольшим локальным помощником; отдельное окно VPN-клиента
не требуется. Сервер и конфигурационный файл предоставляет пользователь.

## Один файл для установки и передачи

1. Запустите **`ZeroOmega-WG-Setup.exe`**. Распаковывать архив или вручную
   запускать PowerShell не нужно. Этот же EXE можно передать другому человеку.
2. Установщик копирует помощник и расширение в
   `%LOCALAPPDATA%\ZeroOmegaWG`, регистрирует Native Messaging для текущего
   пользователя, запускает помощник и проверяет его ответ. Права администратора
   и изменение системной политики PowerShell не нужны. Скачать или запустить
   неподписанный EXE может потребоваться подтвердить средствами Windows.
3. **Chrome:** в открывшейся инструкции указан полный путь. Откройте
   `chrome://extensions`, включите режим разработчика, нажмите «Загрузить
   распакованное расширение» и выберите
   **`%LOCALAPPDATA%\ZeroOmegaWG\chrome`** — в диалоге подставьте свой полный путь.
   Имя дополнения — **ZeroOmega WG**. Исходный ZeroOmega лучше отключить:
   два расширения не должны одновременно управлять настройками прокси.
4. После установки EXE можно удалить: файлы уже находятся в постоянной папке
   приложения. В меню «Пуск» есть ярлык **ZeroOmega WG** с инструкцией.
5. **Firefox:** установленный в папку приложения `firefox/zeroomega-wg-unsigned.xpi`
   ещё не подписан. Для постоянной установки обычный Firefox требует подпись
   Mozilla. Отправьте XPI на подпись как **unlisted / самостоятельное
   распространение**, затем устанавливайте полученный подписанный XPI через
   меню дополнений «Установить дополнение из файла». Публичная страница в
   каталоге не нужна. Подписанный файл можно передавать другим пользователям.

Для временной проверки Firefox можно распаковать XPI в отдельную папку и
загрузить её `manifest.json` через `about:debugging` → «Этот Firefox» →
«Загрузить временное дополнение». После перезапуска браузера такая установка
исчезает. Это не заменяет подпись для постоянного использования.

Документация Mozilla:
[подпись и самостоятельное распространение](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/).
Учётная запись Mozilla, отправка на подпись и сама подпись в комплект не входят.

Для ручной установки также сохранён ZIP-комплект: распакуйте его и выполните
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1`.
Результат тот же: расширение копируется в постоянную папку приложения.
Для установки без открытия окон: `ZeroOmega-WG-Setup.exe --NoOpen` или
`install.ps1 -NoOpen`. Это всё равно запускает и проверяет помощник.

## Подключение и auto switch

1. В настройках создайте профиль **WireGuard / AmneziaWG**.
2. Импортируйте `.conf` или вставьте его текст. Тип определяется по параметрам
   конфига. Сохраните профиль и примените изменения настроек.
3. Для проверки выберите этот профиль в меню расширения: веб-запросы браузера
   пойдут через него. Состояние «Подключён» появляется после успешного обмена
   с сервером; само создание профиля ещё не подтверждает доступность сервера.
4. Для выборочного подключения выберите **auto switch**, добавьте правило
   домена или маски хоста и укажите созданный профиль. Профиль по умолчанию —
   **Напрямую**. Примените изменения и включите auto switch.

Каждое правило относится к домену конкретного запроса. Если страница использует
другие домены для API, картинок или входа, для них при необходимости добавляются
отдельные правила. Можно использовать несколько серверов для разных сайтов.

Кнопка «Отключить» останавливает туннель и приостанавливает его автоматическое
переподключение в текущем сеансе фонового процесса расширения. После перезапуска
браузера активные правила снова запускают нужные туннели. Переключение на другой
профиль само по себе не останавливает туннель: его может использовать второй браузер.

Если выбранный сервер или помощник недоступен, соответствующие запросы
завершаются ошибкой, а не переключаются напрямую. Остальные домены продолжают
работать по своим правилам. Отключение или удаление самого дополнения возвращает
управление прокси браузеру: это не системный аварийный выключатель VPN.

## Конфиги, обновление и удаление

Конфиги хранятся локально в `%LOCALAPPDATA%\ZeroOmegaWG\configs` с защитой
Windows DPAPI, привязанной к текущему пользователю Windows. Приватные ключи не
входят в обычный экспорт настроек ZeroOmega. Такой экспорт переносит правила и
ссылки на профили, но на другом компьютере нужно повторно импортировать `.conf`.
Исходный `.conf` храните отдельно; не публикуйте его и не отправляйте в отчёты.

Маршрут включается только после проверки ссылки на конфиг у местного помощника.
Экспорт PAC не переносит WG/AWG-подключение: такие записи в отдельном PAC остаются
заблокированными, поскольку там нет проверки помощника. Для переноса используйте
резервную копию настроек и повторный импорт исходного `.conf`.

Для обновления полностью закройте Chrome и Firefox и запустите новый
`ZeroOmega-WG-Setup.exe`. Установщик сохраняет конфиги, обновляет файлы в прежней
папке и запускает помощник. После открытия Chrome нажмите «Обновить» на странице
расширений. Если браузер держит файл помощника открытым, установщик попросит
закрыть браузеры и повторить запуск. Для Firefox установите новую подписанную
версию. Идентификаторы дополнений в этом форке закреплены.

Для удаления приложения откройте PowerShell в `%LOCALAPPDATA%\ZeroOmegaWG`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\uninstall.ps1
```

Конфиги сохраняются. Чтобы удалить и их, добавьте `-RemoveConfigs`.
Установленные файлы расширения и ярлык удаляются; запись дополнения удалите
отдельно в браузере. Когда дополнение отключено или удалено, браузер возвращается
к обычной маршрутизации. Системной блокировки прямого доступа после удаления нет.

## Границы первой версии

- Только Windows x64; Chrome и Firefox на одном компьютере используют одного
  помощника, но сохраняют настройки расширения независимо.
- WireGuard и AmneziaWG через `.conf`. Универсальные ключи Amnezia `vpn://`,
  Shadowsocks и SOCKS5 с паролем в Chrome в этот патч не входят.
- Неизвестные/неподдерживаемые поля конфига выдаются как ошибка, а команды
  `PreUp`, `PostUp`, `PreDown`, `PostDown` не исполняются.
- Это проксирование веб-запросов браузера, а не всего компьютера. WebRTC,
  системные приложения и иные обходящие браузерный прокси соединения не входят
  в обещание туннелирования. Системные маршруты не меняются.
- Для сквозной проверки нужны действительные тестовые серверы. Сборка и
  локальные тесты сами по себе не подтверждают подключение к вашему серверу.
- Пакет подготовлен для самостоятельной установки; подписи Mozilla,
  Authenticode и публикации в магазинах в нём нет.

## Сборка из исходников

Команды сборки рассчитаны на Linux/WSL; готовый комплект устанавливается в
Windows. Нужны Node.js 20+ (сборка проверяется на Node.js 22), npm, Python 3,
Git, Go 1.25+ и доступ к реестрам зависимостей. Из корня репозитория:

```sh
python3 scripts/build-windows-kit.py --install-deps
```

Скрипт устанавливает зависимости внутри проекта, связывает его локальные
модули без глобального `npm link`, собирает расширение и Windows x64 помощник.
Результаты — `dist/ZeroOmega-WG-Setup.exe` для передачи одним файлом и
`dist/zeroomega-wg-windows-x64.zip` для ручной установки. EXE встраивает этот ZIP,
распаковывает его во временную папку, запускает установку и удаляет временные
файлы. При уже установленных зависимостях уберите `--install-deps`.
Путь к Go можно передать через `--go`.
При готовом расширении доступен `--skip-extension-build`.

В комплект включены `COPYING`, `AUTHORS`, уведомления зависимостей,
`source/zeroomega-wg.patch` и `source/zeroomega-wg-source.zip` с исходниками
форка и использованных Go-зависимостей. Архив исходников можно распаковать и
собрать помощник из `native-helper` командой `go build -mod=vendor .`.
Метаданные версий и хеш патча находятся в `BUILD-INFO.json`.

Локальные проверки упаковки:

```sh
python3 scripts/test_windows_kit.py
(cd distribution/setup && go test ./...)
```
